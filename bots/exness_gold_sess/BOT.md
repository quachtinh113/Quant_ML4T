### 3. Pre-declaration: a scale-independent staleness screen for the NEXT generation

Written **2026-09-08, before one number of it has been computed**, as
`RULINGS_2026-09-08.md` (c) item 4 requires. It **stands beside** `05`'s existing staleness screen
and does **not** replace it; the existing screen is shared with four case studies whose run logs
are not empty, and rewriting a screen after seeing which column it missed is a threshold moved
after a result.

The defect being addressed is a **definition**, not a threshold: `05_evaluation.py:333-349`
measures the share of consecutive **bit-identical** values, which asks "does this column repeat?"
and not "does this column vary?". `kalman_smoothness` scored **0.0974** against a ceiling of 0.50
and passed while its whole range was 5.55 parts per million wide.

**The replacement screen, and its thresholds, fixed now:**

| Statistic | Computed on | Threshold (fixed 2026-09-08) | Verdict when breached |
|---|---|---|---|
| `n_unique / n` | each column, pooled and per (fold, symbol) | `< 0.01` | **STOP** - fewer than one distinct value per hundred rows |
| relative dispersion `CV = std / |mean|` | each column, per (fold, symbol), median over cells | `< 1e-6` | **STOP** - variation below single-precision resolution of its own level |
| the same `CV`, median over cells | as above | `1e-6 <= CV < 1e-4` | **REVISE** - reported, not dropped |
| share of rows equal to the column's modal value | pooled | `> 0.20` | **REVISE**; `> 0.50` **STOP** |

Three properties of the design, declared with it so they cannot be chosen later:

- **Scale-independent**: every statistic is a ratio, so a column measured in units of `1e10` and
  the same column measured in units of 1 get the same verdict. That is exactly the axis the
  bit-identity screen cannot see.
- **Zero-mean safe**: a column whose mean is at or near zero (a z-score, a centred return) has no
  meaningful `CV`, so for `|mean| < std` the CV test is **not applied** and only the `n_unique / n`
  and modal-share tests run. Declared now, because "the CV blew up on a centred column" is
  otherwise discovered later and fixed in the permissive direction.
- **It is a screen, not a gate on results**: it may STOP a column before any label is scored, and
  it may never be consulted after an IC is known. Applied to `kalman_smoothness` as it stood, it
  would have STOPped on the second row of the table (median CV between 2e-11 and 1.2e-7, below
  1e-6) and on the fourth (22.04 % of rows exactly `1e10`, above 0.20 - REVISE). Both readings are
  written here **before** the screen exists, so the first time it runs it is a test and not a
  procedure.
